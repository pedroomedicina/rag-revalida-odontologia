## C. Code correctness (verified)

1. **`doc_id` shifts when any file is added.** IDs are `prefix-<index in sorted filenames>-slug`. Adding `acceso_cameral.pdf` changed 6/6 existing IDs. That breaks citations, gold labels, and the index (old chunk rows remain).
2. **Index never removes rows.** No `DELETE`/`TRUNCATE` anywhere; chunk IDs are positional (`-ch-0001`). Re-chunking leaves stale rows retrievable.
3. **Keyword retrieval ANDs every question word** (`plainto_tsquery`). `¿cuándo se indica el hidróxido de calcio en endodoncia?` → `'¿cuand' & 'indic' & 'hidrox' & 'calci' & 'endodonci'`, so it fails against a chunk that says "El hidróxido de calcio se indica…". The `¿` sticks to the first word. Accent mismatch: `medicacion` → `'medicacion'`, `medicación` → `'medic'`. Expect the keyword branch to return few or no hits for real questions, so "hybrid" is mostly vector.
4. **e5 prefixes missing** (`query:`/`passage:`) and **IVFFlat `lists=100` built on an empty table with default `probes=1`**. On the 5-chunk sample, prefixes didn't change ranks (margins slightly larger), so this can't be decided without the real corpus.
5. **Citation validator gaps** (`answer_with_rag.validate_citations`), all returning zero errors under `--strict-citations`:
   - `suficiente` with an empty `fuentes` list
   - invented `evidence_id`/citation in `fragmentos_de_apoyo`
   - citations written inline in `respuesta`
6. **Smoke test can't take a DSN**: `retrieval_smoke_test.py --dsn …` → "unrecognized arguments". It needs `-- --dsn …`.
7. **Defaults diverge**: running `generate_inventory_csv.py` alone writes `ENDODONCIA / guia_apunte / media`; via the orchestrator it writes `Endodoncia / guia/apunte / homogenea`.
8. **Authority level is never used in ranking**, although the roadmap requires it.
9. `answer_with_rag.py` runs retrieval in a subprocess per question (reloads both models, ~2.5 s overhead from cache).
10. No unit tests, no CI.
